Kubernetes Resource Requests 与 Limits ​

Kubernetes 通过 requests 和 limits 管理容器资源。

  • requests：容器期望获得的资源，调度器据此选择节点。
  • limits：容器最多能使用的资源，运行时据此限制容器。

常见资源：

  • CPU
  • Memory
  • 临时存储 ephemeral-storage

CPU ​

CPU 可以写成核心数或 millicpu：

yaml
resources:
  requests:
    cpu: 100m
  limits:
    cpu: 500m

100m 表示 0.1 个 CPU 核心，1000m 等于 1 个 CPU。

CPU 超过 limit 时通常会被限流，不会直接杀死容器。

Memory ​

yaml
resources:
  requests:
    memory: 128Mi
  limits:
    memory: 512Mi

内存超过 limit 时，容器可能会被 OOMKilled。

查看：

shell
kubectl describe pod <pod-name>
kubectl get pod

如果状态中出现 OOMKilled，通常说明内存 limit 太小或应用内存泄漏。

完整示例 ​

yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: app
  template:
    metadata:
      labels:
        app: app
    spec:
      containers:
        - name: app
          image: nginx
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 500m
              memory: 512Mi

QoS 等级 ​

Kubernetes 会根据 requests/limits 给 Pod 分配 QoS 等级。

QoS条件驱逐优先级
Guaranteed每个容器 CPU/Memory request 和 limit 都相等最低
Burstable至少设置了一个 request 或 limit，但不满足 Guaranteed中等
BestEffort没有设置任何 request/limit最高

查看：

shell
kubectl get pod <pod-name> -o jsonpath='{.status.qosClass}'

生产服务通常至少设置 requests，避免成为 BestEffort。

LimitRange ​

LimitRange 可以给 Namespace 设置默认资源值：

yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: default-limits
  namespace: dev
spec:
  limits:
    - type: Container
      defaultRequest:
        cpu: 100m
        memory: 128Mi
      default:
        cpu: 500m
        memory: 512Mi

这样没有显式设置 resources 的容器也会得到默认 requests/limits。

ResourceQuota ​

ResourceQuota 限制 Namespace 总资源用量：

yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: dev-quota
  namespace: dev
spec:
  hard:
    pods: "20"
    requests.cpu: "4"
    requests.memory: 8Gi
    limits.cpu: "8"
    limits.memory: 16Gi

查看：

shell
kubectl get quota -n dev
kubectl describe quota dev-quota -n dev

临时存储 ​

容器写入层、日志、emptyDir 都可能占用临时存储。

yaml
resources:
  requests:
    ephemeral-storage: 1Gi
  limits:
    ephemeral-storage: 2Gi

临时存储超限可能导致 Pod 被驱逐。

排查命令 ​

shell
# 查看资源配置和事件
kubectl describe pod <pod-name>

# 查看节点资源
kubectl describe node <node-name>

# 查看实时用量，需要 metrics-server
kubectl top pod
kubectl top node

建议 ​

  • 所有生产工作负载都设置 CPU/Memory requests。
  • Memory limit 不要过低，避免频繁 OOMKilled。
  • CPU limit 是否设置要结合延迟敏感度判断，过低会导致限流。
  • Namespace 级别使用 LimitRange 和 ResourceQuota 做兜底。
