Kubernetes Service ​

Pod 的 IP 会随着 Pod 重建而变化。Service 用来在一组 Pod 前面提供一个稳定的访问入口。

Service 解决两个核心问题：

  • 稳定地址：客户端访问 Service，而不是直接访问 Pod IP。
  • 负载均衡：Service 会把请求转发到后端匹配的 Pod。

Service 与 Pod 的关系 ​

Service 通过 selector 选择 Pod：

yaml
apiVersion: v1
kind: Service
metadata:
  name: hellok8s
spec:
  selector:
    app: hellok8s
  ports:
    - port: 80
      targetPort: 3000

只要 Pod 带有 app: hellok8s 标签，就会成为这个 Service 的后端。

text
client -> Service -> EndpointSlice -> Pod

Kubernetes 会根据 selector 自动维护 EndpointSlice，记录真实后端 Pod 的 IP 和端口。

Service 的类型 ​

ClusterIP ​

默认类型，只能在集群内部访问。

yaml
apiVersion: v1
kind: Service
metadata:
  name: hellok8s
spec:
  type: ClusterIP
  selector:
    app: hellok8s
  ports:
    - port: 80
      targetPort: 3000

集群内其他 Pod 可以通过 DNS 访问：

text
hellok8s.default.svc.cluster.local

同一个命名空间内可以直接访问：

text
hellok8s

NodePort ​

NodePort 会在每个节点上打开一个端口，把流量转发到 Service。

yaml
apiVersion: v1
kind: Service
metadata:
  name: hellok8s-nodeport
spec:
  type: NodePort
  selector:
    app: hellok8s
  ports:
    - port: 80
      targetPort: 3000
      nodePort: 30080

访问方式：

text
http://<node-ip>:30080

NodePort 默认端口范围通常是 30000-32767。

LoadBalancer ​

LoadBalancer 通常用于云环境，由云厂商创建外部负载均衡器。

yaml
apiVersion: v1
kind: Service
metadata:
  name: hellok8s-lb
spec:
  type: LoadBalancer
  selector:
    app: hellok8s
  ports:
    - port: 80
      targetPort: 3000

在本地 minikube 中，可以使用：

shell
minikube service hellok8s-lb

ExternalName ​

ExternalName 不代理流量，只把 Service 名称映射到外部 DNS。

yaml
apiVersion: v1
kind: Service
metadata:
  name: external-api
spec:
  type: ExternalName
  externalName: api.example.com

集群内访问 external-api 时，会解析到 api.example.com。

端口字段 ​

Service 中常见三个端口字段：

yaml
ports:
  - port: 80
    targetPort: 3000
    nodePort: 30080
  • port：Service 暴露的端口。
  • targetPort：后端 Pod 容器监听的端口。
  • nodePort：NodePort 类型在节点上暴露的端口。

如果容器端口有名称，也可以使用命名端口：

yaml
ports:
  - name: http
    port: 80
    targetPort: http

无 selector 的 Service ​

Service 也可以不写 selector，手动维护 EndpointSlice。这适合把集群外服务包装成集群内服务名。

yaml
apiVersion: v1
kind: Service
metadata:
  name: external-db
spec:
  ports:
    - port: 5432
      targetPort: 5432

Headless Service ​

如果设置 clusterIP: None，Service 不会分配虚拟 IP。DNS 会直接返回后端 Pod IP。

yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql
spec:
  clusterIP: None
  selector:
    app: mysql
  ports:
    - port: 3306

Headless Service 常用于 StatefulSet，让每个 Pod 拥有稳定的 DNS 名称。

Service 的操作 ​

shell
# 查看 Service
kubectl get svc

# 查看详情
kubectl describe svc <service-name>

# 查看后端
kubectl get endpoints
kubectl get endpointslice

# 临时转发到本地
kubectl port-forward svc/<service-name> 8080:80

# 删除
kubectl delete svc <service-name>

排查思路 ​

Service 访问不通时，按这个顺序查：

shell
# 1. Service 是否存在，端口是否正确
kubectl get svc hellok8s -o wide

# 2. selector 是否能匹配 Pod
kubectl get pod -l app=hellok8s -o wide

# 3. 是否生成后端 EndpointSlice
kubectl get endpointslice -l kubernetes.io/service-name=hellok8s

# 4. Pod 自身是否监听 targetPort
kubectl describe pod <pod-name>
kubectl logs <pod-name>

最常见的问题是 Service selector 和 Pod label 不匹配。
